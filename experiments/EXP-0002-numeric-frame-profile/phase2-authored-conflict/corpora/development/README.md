# EXP-0002 development corpus

Status: authored development input, non-authoritative and non-executing.

`corpus.json` contains 16 closed cases for the three unselected development
sweep candidates (`strict`, `micro`, and `stress`).  It is an input package for
a later candidate runner; it does not select a profile, run a candidate, make
a resolver decision, create a snapshot, or create experiment evidence.

The cases cover the unchanged Attachment equation, exact translation
boundary/immediate-nextafter pairs for each candidate, a broad translation
conflict, quaternion `q/-q` equivalence, two conservative-margin rotation
separations, arithmetic/gate/square-root/zero-quaternion typed failures, and
top-level rejection of a negative relative-tolerance override.  Transport
malformed and oversize records belong to the runner and are intentionally not
in this corpus.  No descendant equation fixture is included in this
development epoch.

Each case binds the committed stylized fixture path and SHA-256, bounded
`replace` mutations, provider declarations, optional tolerance overrides, and
one expectation for every sweep profile ID.  Expectations contain only stable
classification/cause fields; display details are deliberately excluded.

The loader in `scripts/development_corpus.py` rejects duplicate keys,
symlinked files or path components, missing JSON Pointer-like paths, unsafe
pointers, duplicate mutations, replacement type changes, unknown fields,
resource-limit violations, fixture/materialization hash drift, and any case
mutation or provider/expectation change outside the frozen contract for that
case ID.  A materialization hash is checked in addition to, not in place of,
the closed semantic case contract.  Translation cases extract the materialized
authoritative socket value and prove that it maps to the recorded `value_bits`;
rotation, q/-q, zero-quaternion, provider, and tolerance cases likewise bind
their exact target paths and values.  Stable expected cause fields are checked
against the closed case vocabulary.  The base fixture and every materialized
source are bounded to the candidate transport's 24 KiB decoded-source limit,
so accepted cases remain executable by the later runner.

The translation oracle uses exact `Fraction` arithmetic for `A/(1-R)` and proves
the recorded binary64 value and its immediate successor.  The rotation oracle
uses an exact rational inequality for the normalized `(0, 0, z, 1)` pair and
requires a conservative margin; it does not call candidate code.

Materialized source bytes are deterministic development-generated JSON: keys
are sorted and authored `Decimal` number lexemes are emitted without a
float-round-trip.  They are not claims that the original source formatting was
preserved.  Every case records the SHA-256 of those generated bytes, and the
loader verifies that hash before accepting the corpus.

From the repository root:

```bash
PYTHONPATH=experiments/EXP-0002-numeric-frame-profile/phase2-authored-conflict/scripts \
  python3 experiments/EXP-0002-numeric-frame-profile/phase2-authored-conflict/scripts/development_corpus.py
```

The command only validates the package and prints its case count.
